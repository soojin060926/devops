# 7주차: 도커 컴포즈

## 1. 이번 주 핵심 개념

- 컴포즈(Compose) : 여러 요소를 조합하여 하나의 완성된 것을 만든다 / 작곡하다
- 도커 : 각각의 악기를 연주하게 하는 도구
- 도커 컴포즈 : 독립된 컨테이너들이 함께 동작하도록 구성 및 관리하는 도구
- 셸 스크립트로 작성하면? : `docker run`을 여러 줄 써야 해서 길고 실수하기 쉽다. 실행 순서, 이미 있는 컨테이너 처리, 정리까지 직접 짜야 한다. Compose는 `compose.yaml` 한 파일에 원하는 상태를 적어 두고 `up` 한 번으로 실행한다
- 여러 컨테이너를 함께 띄워야 하는 이유 : 실제 서비스는 웹, DB, 캐시(redis)처럼 역할이 나뉜 여러 프로그램으로 이루어져 있고, 각각을 컨테이너로 분리하면 관리와 교체가 쉽다
- 컨테이너 네트워크 (IP가 아닌 이름을 작성) : 컨테이너 IP는 다시 만들 때마다 바뀔 수 있어서, IP 대신 서비스 이름(예: `redis`)으로 접속한다
- 컨테이너끼리 서비스 이름으로 통신하는 원리 : Compose가 같은 네트워크를 만들고, 그 안의 DNS가 서비스 이름을 해당 컨테이너의 IP로 바꿔 준다
- 볼륨의 필요성 : 컨테이너를 지우면 안의 데이터도 사라지기 때문에, 데이터를 컨테이너 밖에 따로 보관해야 한다
- 볼륨의 동작 : 컨테이너를 지우거나 다시 만들어도 볼륨은 남아 있어서, 새 컨테이너가 같은 볼륨을 연결하면 데이터가 이어진다
- YAML 주의사항 : 들여쓰기가 문법이므로 탭이 아닌 공백을 쓰고(그래서 `nano -ET2`), 들여쓰기 칸 수를 통일한다. `:` 뒤에는 공백이 필요하다
- 네트워크 격리 : 같은 네트워크에 속한 컨테이너끼리만 통신할 수 있고, 다른 네트워크의 컨테이너는 접근하지 못한다
- .env : 비밀번호, 포트 같은 설정값을 코드와 분리해서 저장하는 파일. compose.yaml에서 불러와 쓴다

## 2. 실습한 명령어

- `docker compose config -q` : compose.yaml에 문법 오류가 없는지 유효성을 검사한다 (오류가 없으면 아무것도 출력하지 않는다)
- `nano -ET2 compose.yaml` : 탭을 공백으로 바꾸고(`-E`) 탭 크기를 2칸(`-T2`)으로 해서 compose.yaml을 편집한다
- `docker compose up -d` : compose.yaml에 적힌 대로 컨테이너와 네트워크를 만들고 백그라운드로 실행한다 (지운 뒤 다시 생성할 때도 사용)
- `docker compose ps` : compose로 띄운 컨테이너 목록을 보여준다 (`down` 후에는 아무것도 없음을 확인)
- `docker compose logs web` : `web` 서비스의 로그를 출력한다
- `docker compose logs -f web` : `web` 서비스의 로그를 실시간으로 계속 보여준다 (`-f` = follow)
- `docker compose restart web` : `web`만 재시작한다 (글을 남긴 상태에서 재시작해도 데이터가 유지되는지 확인)
- `docker compose down` : 컨테이너와 네트워크를 전부 삭제한다 (볼륨은 남는다)
- `docker volume ls` : 만들어진 볼륨 목록을 보여준다
- `docker compose down -v` : 볼륨까지 삭제한다. 데이터도 사라진다 (`down`은 컨테이너와 네트워크만 지우고 데이터는 남는다)
- `python3 -c "import socket; socket.create_connection(('127.0.0.1', 6379), timeout=2)"` : 내 컴퓨터의 6379 포트(redis)에 2초 안에 연결되는지 확인한다 (연결되면 아무 출력 없음, 실패하면 오류)
- `docker compose exec web sh` : 실행 중인 `web` 컨테이너 안에 들어가 셸을 연다
- `python -c "import socket; print(socket.gethostbyname('redis'))"` : 컨테이너 안에서 서비스 이름 `redis`가 어떤 IP로 바뀌는지 출력한다 (서비스 이름 통신 확인)
- `docker compose down && docker compose up -d` : 컨테이너를 지우고 바로 다시 만든다 (`&&`는 앞 명령이 성공하면 뒤 명령을 실행)

## 3. 어려웠던 점과 해결

- compose.yaml을 작성할 때 들여쓰기가 맞지 않아 오류가 났다. `docker compose config -q`로 문법을 먼저 검사하고, 공백 2칸으로 통일해서 해결했다.

## 4. 느낀 점

- 컨테이너를 하나씩 띄울 때보다 compose 파일 하나로 여러 개를 한 번에 관리하니 훨씬 편했다. `down -v`로 지우면 데이터까지 사라지는 걸 직접 확인해서 볼륨이 왜 필요한지 이해가 됐다.
