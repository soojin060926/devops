# 3주차: (자동와 협업)

## 1. 이번 주 핵심 개념

- grep와 find : grep는 파일 안의 글자를 찾고, find는 조건에 맞는 파일을 찾는다
- 파이프(`|`) : 앞 명령어의 출력 결과를 뒤 명령어의 입력으로 넘겨준다 
- 리다이렉션(`>`,`>>`) : 명령어 출력 결과를 화면 대신 파일로 저장한다.
- 프로세스 : 실행 중인 프로그램
- tar : 여러 파일을 하나의 아카이브로 묶는 도구
- Conflict : 같은 파일의 같은 부분을 서로 다르게 수정하여 Git이 자동으로 합치지 못하는 상
- Merge :
- 메인 브랜치에 푸시를 막는 방법 : GitHub의 브랜치 보호 규칙을 설정해서 main에 직접 push하지 못하게 하고, PR을 통해서만 합치게 한다.

## 2. 실습한 명령어
- `grep` : 파일이나 출력 결과에서 특정 글자가 들어 있는 줄을 찾는다
- `find` : 이름, 종류 같은 조건으로 파일과 폴더를 찾는다
- `ps aux` : 시스템에서 실행 중인 거의 모든 프로세스를 상세하게 보여주기
- `aux` : a(모든 사용자) u(사용자 중심의 상세) x(터미널에 연결되지 않은 프로세스 포함, 백그라운드 등)
- `htop` : 실행 중인 프로세스, CPU, 메모리 사용량을 실시간으로 확인하는 도구 ( 종료 = q )
- `git ignore` : 저장한 파일을 새로 Git 추적 대상에 포함하지 않도록 한다.
- `gh pr create` : 터미널에서 Pull Request(합쳐 달라는 요청) 을 만듣나
- `gh pr merge --squash --delete-branch` : PR의 커밋들을 하나로 합쳐서 Merge하고, 다 쓴 브랜치는 삭제한다.

## 3. 어려웠던 점과 해결
- `grep`, `find`, 파이프(`|`)를 같이 쓰는 게 헷갈렸다. 하나씩 따로 실행해 결과를 확인한 뒤 `|`로 이어 보니 이해가 됐다.

## 4. 느낀 점
- 혼자 작업할 때는 몰랐는데, 여러 명이 같은 파일을 고치면 충돌이 생길 수 있다는 걸 직접 겪어 보니 PR과 Merge 과정이 왜 필요한지 이해가 됐다. 앞으로 브랜치를 나눠서 작업하는 습관을 들이고 싶다.
