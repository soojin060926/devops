# 5주차: 도커

## 1. 이번 주 핵심 개념

- 하이퍼바이저(VM) : 하드웨어 위에서 가상 컴퓨터(VM)를 여러 개 만들어 실행하게 해 주는 소프트웨어. VM마다 운영체제를 따로 갖기 때문에 컨테이너보다 무겁다
- 이미지와 컨테이너 관계 : 이미지로 컨테이너를 실행하면 격리된 환경이 생성되고, 그 안에서 프로그램이 프로세스로 실행된다
- 이미지(Image) : 컨테이너를 만들기 위한 읽기 전용 템플릿
- 컨테이너(Container) : 이미지로부터 생성된 인스턴스
- Dockerfile : 이미지를 어떻게 만들지 작성하는 파일
- Registry : 이미지를 저장 및 공유하는 곳 (예: Docker Hub)
- Docker : 애플리케이션을 개발, 배포, 실행하기 위한 오픈 플랫폼. 애플리케이션과 실행 환경을 컨테이너로 묶어서, 서로 다른 환경에서도 비교적 동일하게 실행할 수 있도록 도와준다
- 컨테이너 격리 : 컨테이너끼리 서로 영향을 주지 않도록 환경을 나누는 것
  - namespace : 시야 격리 - "안 보이게 만들기"
  - cgroup : 자원 사용량 제한 및 관리 - "많이 못 쓰게 만들기"

## 2. 실습한 명령어

- `docker --version` : 설치된 Docker 버전을 출력한다. 정상적으로 설치됐는지 확인할 때 쓴다
- `docker run hello-world` : hello-world 이미지를 내려받아 컨테이너로 실행한다. Docker가 잘 동작하는지 확인하는 용도다
- `wsl --shutdown` : 윈도우에서 실행 중인 WSL을 모두 종료한다. WSL이나 Docker가 이상할 때 재시작하려고 쓴다
- `docker run -d -p 8080:80 --name web nginx` : nginx 컨테이너를 백그라운드(`-d`)로 실행하고, 내 컴퓨터의 8080 포트를 컨테이너의 80 포트에 연결(`-p`)하며, 이름을 `web`으로 지정(`--name`)한다
- `docker ps` : 현재 실행 중인 컨테이너 목록을 보여준다
- `docker ps -a` : 중지된 컨테이너까지 포함해서 모든 컨테이너를 보여준다
- `docker start` : 중지된 컨테이너를 다시 시작한다
- `docker exec -it web bash` : 실행 중인 `web` 컨테이너 안에 들어가서 bash 터미널을 연다
- `docker rm -f <컨테이너 이름1> <컨테이너 이름2> ...` : 컨테이너를 강제로 삭제한다
- `docker system df` : Docker가 사용 중인 디스크 사용량을 확인한다

## 3. 어려웠던 점과 해결

- 실수로 계속 같은 포트의 컨테이너를 만들고 있었는데 무엇이 잘못된 줄 몰라 헤매다가, 교안을 보며 같은 포트가 이미 사용 중이라는 것을 확인하고 해결하였다

## 4. 느낀 점

- 컨테이너를 직접 만들고 지우면서 이미지와 컨테이너의 관계가 이해됐다. 포트가 겹치면 실행이 안 된다는 걸 직접 겪어 보니, 앞으로는 `docker ps`로 먼저 확인하고 실행하고 싶다.
